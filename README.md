# 문서 서재 — PDF 책 보기 (기기 간 동기화판)

학습 자료 PDF를 노트북에서는 양쪽 보기, 휴대폰에서는 한 면 보기로 읽는 웹앱입니다.
Supabase에 로그인하면 **책갈피와 마지막으로 읽은 쪽**이 기기 사이에 맞춰집니다.
PDF 파일 자체는 서버로 올라가지 않습니다.

> 연습용 개인 도구입니다. 코드 안의 주석과 이 문서의 ↳ 설명을 함께 보세요.

```
pdf-bookshelf/
├─ index.html            화면 + 모든 동작 (한 파일)
├─ config.js             Supabase 주소와 Publishable 키 (직접 채움)
├─ lib/
│  ├─ pdf.min.js         PDF.js 3.11.174 (PDF 그리기)
│  ├─ pdf.worker.min.js  PDF.js 일꾼 (무거운 해석을 따로 돌림)
│  └─ supabase.js        supabase-js 2.119.0 (로그인·DB 요청)
├─ sql/01_doc_state.sql  테이블 + RLS 만들기
└─ sql/02_add_shelf.sql  책장 칸 더하기 (01 다음에 한 번)
```

## 1. 처음 설정 (한 번만)

### 1-1. Supabase에 테이블 만들기

1. Supabase 대시보드 → `hanja-v2-dev` 프로젝트 → **SQL Editor** → New query
2. `sql/01_doc_state.sql` 내용을 통째로 붙여 넣고 **Run**
3. 맨 아래 결과에 `doc_state | true` 가 보이면 됩니다.
   (실행 중 `... does not exist, skipping` 안내가 몇 줄 보이는 것은 정상입니다. 처음 만들 때 "지울 것이 없어 건너뜀"이라는 뜻입니다.)

↳ SQL 안의 `grant` 줄이 빠지면 로그인해도 `permission denied for table doc_state` 오류로 동기화가 안 됩니다. 2026년부터 Supabase는 새 테이블을 API에 자동으로 열어 주지 않습니다.
↳ `true`는 RLS(행 수준 보안)가 켜졌다는 뜻입니다. 이것이 꺼져 있으면 Publishable 키를 가진 누구나 표를 읽을 수 있습니다.
↳ Table Editor에서 `doc_state` 옆에 RLS 표시가 켜져 있는지도 한 번 눈으로 확인해 두면 좋습니다.

### 1-2. GitHub Pages에 올리기

1. GitHub에서 새 저장소 `pdf-bookshelf` 만들기 (Public — 무료 계정의 Pages는 공개 저장소에서 동작)
2. 이 폴더의 파일을 그대로 올리기 (`Add file → Upload files`, 폴더 구조 유지)
3. 저장소 **Settings → Pages** → Source: `Deploy from a branch`, Branch: `main` / `(root)` → Save
4. 1~2분 뒤 주소가 생깁니다: `https://<GitHub아이디>.github.io/pdf-bookshelf/`

↳ 저장소가 공개라서 `config.js`의 주소와 Publishable 키도 공개됩니다. **이 둘은 원래 브라우저에 두는 값**이라 괜찮습니다. 데이터를 지키는 것은 키가 아니라 RLS입니다.
↳ 반대로 `sb_secret_`로 시작하는 Secret 키는 절대 넣지 않습니다(프로젝트 지킬 것).

### 1-3. Supabase 로그인 설정

대시보드 **Authentication** 메뉴에서 (메뉴 이름은 Supabase 화면 개편에 따라 조금 다를 수 있습니다)

| 할 일 | 위치 | 값 |
|---|---|---|
| 확인 메일 링크가 돌아올 주소 | URL Configuration → Site URL | `https://<GitHub아이디>.github.io/pdf-bookshelf/` |
| 같은 주소를 허용 목록에 | URL Configuration → Redirect URLs | 위와 같은 주소 |
| 비밀번호 최소 길이 | Sign In / Providers → Email | 8 이상 |

↳ Site URL을 안 바꾸면 확인 메일의 링크가 `localhost:3000`으로 가서 "사이트에 연결할 수 없음"이 뜹니다.

### 1-4. config.js 채우기

대시보드 상단 **Connect** 버튼(또는 Project Settings → API Keys / Data API)에서 두 값을 복사합니다.

```js
window.PDFBOOK_CONFIG = {
  supabaseUrl: "https://xxxxxxxx.supabase.co",     // Project URL
  supabaseKey: "sb_publishable_xxxxxxxxxxxxxxxx"   // Publishable key
};
```

GitHub에서 `config.js`를 연필(✏️) 버튼으로 고쳐 Commit 하면 됩니다.

### 1-5. 가입 → 가입 막기

1. 노트북에서 Pages 주소를 열고 **처음 가입** (이메일 + 비밀번호 8자 이상)
2. 메일의 확인 링크를 누르면 서재 화면으로 돌아와 로그인됩니다.
3. 휴대폰에서는 같은 주소를 열고 **로그인**만 합니다.
4. **Authentication → Sign In / Providers → "Allow new users to sign up" 끄기**

↳ 4번이 중요합니다. 주소를 아는 다른 사람이 가입해도 RLS 때문에 내 책갈피는 못 보지만, 남의 계정이 내 프로젝트에 쌓이는 것 자체를 막는 편이 깔끔합니다.

## 2. 쓰는 법

### 서재와 책장
- **＋ 서재에 넣기** 또는 PDF를 서재 화면에 **끌어다 놓기** → 지금 고른 책장에 들어가기만 하고 열리지는 않습니다. ('전체'를 보고 있으면 '분류 없음')
- **바로 읽기** → 서재에 넣지 않고 이번 한 번만 봅니다. 읽던 쪽·책갈피·목차 어느 것도 기기에 저장하지 않습니다. 읽다가 계속 보고 싶으면 위쪽 「서재에 넣기」.
- 책장: 「＋ 새 책장」으로 만들고, 문서마다 '책장' 목록에서 옮깁니다. 책장을 고른 상태에서 「이름 바꾸기」「책장 없애기」(문서는 '분류 없음'으로).
- 정렬: 최근 넣은 순(기본) / 가나다순. 가나다순은 숫자를 숫자로 읽어 2 → 10 순서가 됩니다.
- 책갈피: 양쪽 보기에서 ☆(또는 B 키)를 누르면 왼쪽·오른쪽 쪽을 고르는 메뉴가 뜹니다.

### 동기화

- 책갈피를 꽂거나 쪽을 넘기면 **3초 모았다가** 서버에 올립니다. 앱을 닫거나 다른 탭으로 가면 바로 올립니다.
- 문서를 열 때는 그 문서의 서버 기록을 먼저 확인합니다. 노트북에서 50쪽까지 읽었으면 휴대폰에서 50쪽부터 열립니다.
- 다른 기기에만 있는 문서는 서재에 **"이 기기에는 PDF가 없습니다"** 로 보입니다. 눌러서 같은 이름의 PDF를 넣으면 책갈피가 그대로 붙습니다.
- **삭제**는 PDF 파일, 읽던 쪽, 책갈피, 서버 기록을 모두 지웁니다. 다른 기기도 다음 동기화 때 같은 문서를 지웁니다. 같은 이름의 파일을 다시 넣으면 1쪽부터 새로 시작합니다.
- 책장 이름도 동기화됩니다(빈 책장은 그 기기에만 남음).
- 로그아웃해도 이 기기의 서재는 그대로 남습니다.

↳ 일주일에 한 번 이상 열어 쓰면 Supabase 무료 프로젝트의 일시 중지도 함께 막힙니다. 오래 안 쓰면 멈추지만, 대시보드에서 다시 켤 수 있습니다.

## 3. 구간별 설명

`index.html`의 스크립트는 번호 붙은 구간으로 나뉘어 있습니다. 주석의 번호와 같습니다.

### 0. 기본 준비
`$()`는 `document.getElementById`의 줄임, `el()`은 태그를 만드는 도우미입니다.

```js
el("button", { type: "button", text: "삭제" })   // → <button type="button">삭제</button>
```
↳ `text`는 `textContent`로 넣습니다. PDF 파일 이름, 서버에서 온 메모처럼 **바깥에서 온 글자를 innerHTML로 넣지 않기 위해** 이 도우미를 씁니다(보안 기준: 외부 데이터는 textContent).

### 1. 저장소 (IndexedDB)
이 기기 안의 두 상자에 나눠 담습니다.

| 상자 | 키 | 값 |
|---|---|---|
| `files` | 파일 이름 | PDF 파일(Blob) |
| `meta` | 파일 이름 | 쪽 수, 마지막 쪽, 책갈피, 썸네일, `updatedAt`, `hasFile` |

↳ 파일과 정보를 나눈 이유: 쪽을 넘길 때마다 `meta`만 고쳐 쓰면 되므로, 수 MB짜리 PDF를 매번 다시 쓰지 않습니다.
↳ IndexedDB를 못 쓰는 브라우저(일부 사생활 보호 모드)에서는 메모리로 대신하고 안내 문구를 띄웁니다.

### 2. 서재 화면
최근 연 순서로 문서 목록을 그립니다. `hasFile === false`인 문서(다른 기기에서만 연 문서)는 안내 문구를 다르게 보여 줍니다. 삭제는 실수 방지를 위해 두 번 눌러야 합니다(`confirm()`은 쓰지 않음).

### 3. 읽기 상태 / 4. 문서 열기
`S` 하나에 지금 문서, 쪽, 보기 방식, 확대 배율을 모아 둡니다.

```js
spreadOf(5)   // 양쪽 보기 + 표지 따로 → [4, 5]
spreadOf(1)   // → [1]  (표지는 혼자)
```
↳ 실제 책처럼 짝수 쪽이 왼쪽에 옵니다.
↳ `isEvalSupported: false`: PDF 안 글꼴 코드를 `eval`로 실행하지 않게 하는 PDF.js 옵션입니다(PDF.js의 알려진 취약점 대비).

### 5. 쪽 그리기
쪽을 `<canvas>`에 그립니다. 같은 쪽·같은 배율은 최근 12장까지 다시 씁니다. 다음·이전 펼침면은 미리 그려 두어 넘김이 빠릅니다.

↳ `devicePixelRatio`(최대 2.5)를 곱해 그리는 이유: 휴대폰·고해상도 노트북은 CSS 1px에 실제 점이 2~3개라, 그냥 그리면 글자가 흐립니다.
↳ `token`은 "그리는 사이에 다른 쪽으로 넘어갔으면 이 결과는 버린다"는 표시입니다. 빠르게 넘길 때 늦게 끝난 그림이 덮어쓰는 것을 막습니다.

### 6. 넘기기
버튼, 키보드(← → Home End), 화면 좌우 누르기, 손가락 밀기. 스와이프만 되는 것이 아니라 버튼으로도 똑같이 되게 한 것은 접근성 기준(스와이프 대체 수단)입니다.

### 7. 책갈피
☆ 버튼 또는 B 키. 바뀔 때마다 `metaChanged()`를 부릅니다.

```js
function metaChanged() {
  S.meta.updatedAt = Date.now();   // ① 고친 시각 기록 → 동기화에서 "누가 최신인가" 판정
  Store.put("meta", ...);          // ② 이 기기에 저장
  Sync.schedulePush(S.meta);       // ③ 3초 뒤 서버로
}
```

### 8. 목차·찾기·링크
1. PDF에 목차 정보가 있으면 그대로 씁니다.
2. 없으면(한워드 PDF) 글자 크기로 제목을 찾아 **자동 목차**를 만듭니다. 본문 크기보다 1.15배 이상 큰 줄 중 크기 순으로 3단계까지 씁니다.
3. 앞쪽 **차례 쪽**은 "줄 대부분이 쪽 번호로 끝나는 쪽"으로 알아보고, 각 줄 위에 투명 버튼을 겹쳐 눌러서 이동하게 합니다.

↳ 위·아래 여백에 되풀이되는 줄(머리말·꼬리말)과 차례 쪽의 줄은 제목 후보에서 뺍니다.

### 9. 패널·설정·확대
목차·찾기·책갈피·보기 설정 탭. 탭은 ← → 키로도 옮겨 다닙니다(`role="tab"`).

### 10. 기기 간 동기화 (Supabase) ← 이번에 더한 부분

**규칙은 하나입니다: 문서별로 `updated_at`(고친 시각)이 더 늦은 쪽이 이긴다.**

| 함수 | 언제 | 하는 일 |
|---|---|---|
| `pullAll()` | 로그인 직후, '지금 동기화', 앱에 돌아왔을 때(1분 넘게 지났으면) | 서버 전체를 읽어 기기와 비교 → 서버가 최신이면 받고, 기기가 최신이거나 기기에만 있으면 올림 |
| `pullOne(name)` | 문서를 열기 직전 | 그 문서 한 줄만 확인 (3초 넘으면 기다리지 않고 기기 기록으로 엶) |
| `schedulePush(m)` | 책갈피·쪽이 바뀔 때 | 3초 모았다가 `flush()` |
| `flush()` | 위 3초 뒤, 앱을 떠날 때, 로그아웃 전 | 모아 둔 문서를 `upsert`로 올림. 실패하면 30초 뒤 다시 |
| `remove(name)` | 서재에서 삭제 | 서버 줄도 지움 |

```js
// 올리기: 있으면 고치고 없으면 넣기 (user_id + doc_name이 같으면 같은 줄)
await sb.from("doc_state").upsert(rows, { onConflict: "user_id,doc_name" });

// 읽기: 조건을 문자열로 이어 붙이지 않고 라이브러리 메서드로
await sb.from("doc_state").select("...").eq("doc_name", name).maybeSingle();
```
↳ `select`에 `user_id` 조건이 없는데도 내 줄만 오는 이유: RLS 정책 `auth.uid() = user_id`가 DB 안에서 걸러 주기 때문입니다. 브라우저 코드를 누가 고쳐도 남의 줄은 못 가져옵니다.
↳ `cleanBookmarks()`: 서버에서 온 책갈피도 "바깥 데이터"라서 모양(쪽 번호가 정수인가, 메모가 80자 이하인가)을 다시 검사한 뒤 씁니다.
↳ 로그인 5번 실패 → 60초 잠금은 화면 쪽 장치이고, Supabase도 서버에서 따로 횟수를 제한합니다(보안 기준: 반복 실패 제한).
↳ 오류는 사용자에게 "동기화하지 못했습니다…"처럼 짧게만 알리고, 서버의 원래 오류 내용(SQL, 경로)은 보여 주지 않습니다.

### `sql/01_doc_state.sql`

| 부분 | 뜻 |
|---|---|
| `primary key (user_id, doc_name)` | 한 사람의 같은 이름 문서는 한 줄 → `upsert`의 기준 |
| `default auth.uid()` | 로그인한 사람의 id가 자동으로 들어감 |
| `check (...)` 5개 | 서버 쪽 검증: 이름 255자, 쪽 1~100000, 책갈피는 배열·500개·64KB 이하, 미래 시각 금지 |
| `doc_state_touch` 트리거 | `synced_at`을 서버 시각으로 (기기 시계가 틀려도 언제 들어왔는지 알 수 있게) |
| RLS 정책 4개 | 읽기·넣기·고치기·지우기 모두 "본인 줄만" |
| `grant ... to authenticated` | 로그인한 사용자에게 이 테이블을 API로 쓸 권한을 줌. 2026년부터 새 테이블은 자동으로 열리지 않아 꼭 필요 |

↳ 정책에서 `auth.uid()`를 `(select auth.uid())`로 감싼 것은 Supabase가 권하는 성능 요령입니다. 줄마다 함수를 다시 부르지 않고 한 번만 계산합니다.

## 4. 한계와 다음에 해 볼 것

- 두 기기에서 **동시에** 같은 문서의 책갈피를 고치면 나중에 고친 쪽 전체가 이깁니다(책갈피 하나하나를 합치지는 않음). 혼자 쓰는 도구라 단순하게 두었습니다.
- 문서를 고쳐 쪽이 밀리면 책갈피 쪽 번호가 어긋날 수 있습니다.
- 다음에 직접 해 볼 만한 것: 책갈피를 별도 테이블(`bookmarks`)로 나눠 하나씩 합치기, 쪽 번호 대신 목차 제목에 책갈피 걸기.
